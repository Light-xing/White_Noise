## 1. 先用一句话理解

这是一个**纯静态的 H5 单页应用**：没有后端、没有数据库、没有 npm 构建。浏览器打开 `index.html` 后，加载 CSS、Vue 和两个 JS 文件，页面就变成你看到的白噪音应用。

真正需要理解的运行代码只有四个：

```text
index.html   页面骨架 + Vue 模板
style.css    外观、布局、动画
app.js       大脑：状态、播放、音量、定时、上传
scene.js     背景画师：canvas 粒子、雨、海浪、频谱柱
```

其余都是工具库、音频、图片和文档。

### 2.1 本地目录和 GitHub 目录不完全一样

这是你最容易困惑的地方，先记住三句话：

1. **本地 `audio/` 里既有 MP3 也有 WAV**。MP3 是你自己的大文件，已被 `.gitignore` 忽略；WAV 是仓库里的 20 秒占位素材。
2. **代码优先播放 MP3，找不到再播放 WAV**。所以本地会放你的 MP3；GitHub Pages 上没有 MP3，会先 404，然后浏览器自动回退 WAV。
3. **`deploy/` 只在本地**，是服务器部署脚本，没有上传；GitHub 仓库里没有它。

> 线上访问 `audio/white.mp3` 返回 404 是正常现象，不是代码坏了。

## 4. 页面是怎么跑起来的

```text
浏览器打开 index.html
  → 加载 css/style.css
  → 加载 lib/vue.global.prod.js
  → 加载 js/app.js
  → Vue 挂载 #app
  → 把 index.html 里的 {{ ... }}、v-if、v-for 变成真实界面
  → js/scene.js 创建 canvas 背景
  → 用户点按钮，app.js 改状态、控制 audio
  → scene.js 根据播放状态和音量重绘背景
```

`index.html` 里的 `{{ currentSoundMeta.name }}` 只是模板占位符。正常情况下 Vue 会替换；如果 CSS/JS 没加载，就会像用手机文件管理器打开时那样，直接显示 `{{ ... }}`。

## 5. 各功能单元用了什么技术

这张表建议你展示前看两遍。老师问“这个功能怎么做的”，就按“单元 → 技术”回答。

| 功能单元 | 页面上看到什么 | 用到的技术 |
| --- | --- | --- |
| 页面结构 | 标题、卡片、按钮、分区 | HTML5 语义标签 `header` / `main` / `section`；Vue 模板语法 |
| 视觉与布局 | 深色玻璃卡片、四列声音、手机适配 | CSS3 变量、Flex / Grid、渐变、`backdrop-filter`、媒体查询、`clamp()`、`safe-area` |
| 状态与交互 | 选中声音、按钮变“暂停”、错误提示 | Vue 3 全局构建版、Options API、`data` / `computed` / `watch`、`@click`、`:class`、`v-if` / `v-for` |
| 声音选择 | 白噪音 / 雨声 / 海浪 / 自定义 | 数组驱动卡片；`currentSound` 状态；`<source>` 按 `mp3 → wav` 排序 |
| 播放 / 暂停 | 播放按钮、当前声音 | HTMLMediaElement、`audio.play()` 返回 Promise、两个 audio 元素分离 |
| 音量 | 滑动条 0–100 | `<input type="range">`；内置声音写 `audio.volume`；自定义写 `GainNode.gain` |
| 结束前淡出 | 最后 30 秒声音渐弱 | `setInterval` 100ms；`timerEndAt - Date.now()` 算剩余；音量和增益同时乘 `fadeFactor` |
| 定时关闭 | 15 / 30 / 60 分钟 | JavaScript 定时器、状态机、`Date.now()` 时间戳、`audioStarted` 标志 |
| 自定义上传 | 上传按钮、自定义卡片 | File API、`URL.createObjectURL()`、Blob URL、MIME / 扩展名校验、对象 URL 释放 |
| 解析失败提示 | “音频无法解析”弹窗 | 原生 `<dialog>`、`showModal()`、`audio` 的 `error` / `NotSupportedError`、旧浏览器 `alert` 兜底 |
| 动态背景 | 颗粒、雨丝、海浪 | Canvas 2D、`requestAnimationFrame`、`devicePixelRatio`、`visibilitychange`、`matchMedia` |
| 自定义可视化 | 像素柱、峰值、渐变 | Web Audio `AnalyserNode`、FFT、对数频段、软膝压缩、32 级调色板、峰值保持 |
| 锁屏控制 | 手机锁屏 / 通知栏 | Media Session API、`MediaMetadata`、canvas 生成 512×512 封面 |
| 偏好记忆 | 刷新后恢复声音和音量 | `localStorage`、JSON 序列化、异常兜底 |
| 手机适配 | 320 / 375 / 414 不横向滚动 | CSS 媒体查询、弹性布局、触控尺寸、`viewport-fit=cover` |
| 无障碍 | 键盘、读屏、减少动态 | 语义标签、`aria-label` / `aria-pressed`、`:focus-visible`、`prefers-reduced-motion` |
| 部署 | GitHub Pages 在线访问 | Git、GitHub、静态站点、相对路径、Pages 分支构建 |

## 6. 一次操作的完整链路

### 6.1 选雨声并播放

```text
点击“雨声”
  → app.js 的 selectSound('rain')
  → currentSound = 'rain'
  → index.html 里的两个 <source> 变成：
       audio/rain.mp3
       audio/rain.wav
  → 浏览器按顺序加载，优先 MP3

点击播放
  → app.js 的 play()
  → mainAudio.play()
  → 成功后 isPlaying = true，按钮变成“暂停”
  → scene.js 切到雨丝场景
  → 如果之前已经选了定时档位，这时才开始倒计时
```

### 6.2 调音量

```text
拖动滑块
  → volume = 0..100
  → applyOutputVolume()
  → 内置声音：mainAudio.volume = volume / 100 × fadeFactor
  → 自定义音频：gainNode.gain → 输出音量
  → scene.setVolume() → 背景强度变化
```

### 6.3 选定时

```text
暂停时点 15 分钟
  → 显示 15:00，档位高亮，但 timerRunning = false
  → 点播放后 onPlayStarted()
  → beginCountdown() 才真正开始每秒递减
```

### 6.4 上传自定义音频

```text
选择文件
  → 校验非空、< 10MB、音频类型 / 扩展名
  → URL.createObjectURL(file)
  → 自定义卡片启用并选中
  → customAudio.src = blob URL
  → 播放时建立 Web Audio：
       customAudio → GainNode → AnalyserNode → 扬声器
  → AnalyserNode 的频谱送给 scene.js 画像素柱
```

## 8. 老师可能问的问题与答法

| 老师可能问 | 你可以这样答 |
| --- | --- |
| 为什么用 Vue，不用原生 JS？ | 这个项目状态比较多：当前声音、播放状态、音量、定时、错误提示。Vue 的数据绑定和 `v-if` / `v-for` 能让这些状态和界面自动同步，代码更好维护。 |
| 为什么没有 `npm install` / 构建？ | 项目是静态页面，直接用 `vue.global.prod.js` 全局构建版，双击 `index.html` 或放 GitHub Pages 就能跑，不需要 Node 和打包器。 |
| 为什么有两个 `<audio>`？ | 内置声音走普通 audio 元素，音量用元素自带 `volume`；自定义音频要走 Web Audio 的 `GainNode` 和 `AnalyserNode`，拿实时频谱。两条链路分开，避免互相影响。 |
| 为什么内置声音不直接接 Web Audio？ | 在 `file://` 下，本地媒体文件接 `createMediaElementSource` 后可能静音，Analyser 数据也全是 0。所以内置声音保留原生播放，只有自定义音频接 Web Audio。 |
| 音量是怎么统一控制的？ | 内置声音写 `audio.volume`，自定义音频写 `GainNode.gain`，最后都乘同一个 `fadeFactor`。 |
| 为什么选定时后不马上倒计时？ | 需求是“暂停时先预设，播放后才计时”。所以有 `timerRunning` 和 `audioStarted`，真正开始播放后 `onPlayStarted()` 才启动倒计时。 |
| 暂停为什么把定时清掉？ | 需求约定暂停即取消定时，重新播放需要重新选档位；这样不会出现“暂停了但定时还在走”的状态。 |
| 最后 30 秒淡出怎么做的？ | 用 100ms 定时器计算 `timerEndAt - Date.now()`，得到剩余秒数，再算 `fadeFactor`，同时降低元素音量和 GainNode。暂停、切换、取消都会恢复。 |
| 上传文件怎么校验？ | 先看非空、`< 10MB`，再看 MIME 是否 `audio/*` 或扩展名是否常见音频格式。通过后生成 Blob URL，只在当前会话播放，不上传服务器。 |
| 解析失败怎么提示？ | 监听 audio 的 `error` 和 `play()` 的 `NotSupportedError`，用原生 `<dialog>` 弹出明确提示；不支持 dialog 的浏览器退回 `alert`。 |
| 刷新后自定义音频为什么没了？ | 自定义音频是本地 Blob URL，只在当前页面会话有效；刷新后回退白噪音，这是有意的隐私 / 简化设计。 |
| 右端频谱以前不动，怎么解决的？ | 以前线性映射到 20kHz，普通音乐右端几乎没能量。现在改成 35Hz–12kHz 对数频段，取频段内最大值，并做 1.5 倍高频补偿。 |
| 柱子的高度为什么不会顶到最上面？ | 用了软膝压缩：0.55 以下线性，超过后缓慢压缩；实际最高约 0.744。绘制时顶部再留 2 行，任何响度都不会碰到高度线。 |
| 为什么不用 tanh / sigmoid？ | 它们会把中等响度整体抬高，和“正常响度不被妨碍”的目标不一致。软膝压缩更接近音频动态范围处理的常用做法。 |
| 像素柱为什么用 canvas，不用 DOM？ | 几十根柱子、上百个方块，每帧都变；用 DOM 会产生大量节点和重排。canvas 一次绘制，性能更稳。 |
| 背景动画性能怎么保证？ | canvas 按 DPR 绘制但上限 2；resize 延后 150ms；页面切后台停止 `requestAnimationFrame`；系统减少动态时只画静态一帧。 |
| 锁屏控制怎么做的？ | 接入 Media Session API，设置标题、封面和播放 / 暂停 / 停止动作；封面用 canvas 运行时生成，不额外加图片。 |
| 数据存在哪里？ | 只把声音和音量存 `localStorage`，key 是 `whitenoise:v1`；不上传服务器，不自动播放。 |
| 无障碍做了什么？ | 语义标签、`aria-label` / `aria-pressed`、可见焦点、触控尺寸、`prefers-reduced-motion`；axe 自动审计 0 项违规。 |
| 测试怎么做的？ | Chrome 下按 320 / 375 / 414 三种宽度测 12 项验收和 6 个异常场景；另外测了 9.6MB 上传、100Hz + 10kHz 频段、伪造 MP3、axe。 |
| 最大的难点是什么？ | `file://` 下 Web Audio 会静音，所以拆成两个 audio；其次是定时状态和频谱右边不响应，分别用 `audioStarted` 和 35Hz–12kHz 对数频段解决。 |
| 这个项目有什么不足？ | 自定义音频不持久化；iOS 真机未完整验证；后台定时会被浏览器节流；10MB 限制；目前只重点测了 Chrome。 |
| 为什么 GitHub 上没有 MP3 和 deploy？ | MP3 是大文件、涉及版权，放进 `.gitignore` 只留本地；deploy 是服务器部署脚本，按你的要求先不上传。线上用 WAV 兜底。 |
| 为什么手机直接点 `index.html` 显示 `{{ ... }}`？ | 文件管理器给的是 `content://` 地址，Chrome 加载不到同目录 CSS/JS，Vue 没执行。手机演示用 GitHub Pages 或本地 HTTP 服务。 |

## 9. 几个容易讲错的点

- 不要说“这是原生 App”。它是 H5 网页，可以加到主屏幕，但不是 Android / iOS 原生应用。
- 不要说“音频上传到了服务器”。自定义音频只在浏览器本地生成 Blob URL，没有后端。
- 不要把“内置声音”和“自定义音频”混成一条链路。前者是元素音量，后者是 Web Audio。
- 不要说“GitHub 上也有 MP3”。仓库里只有 WAV 占位；MP3 在本地且被忽略。
- 不要说“所有浏览器都测过”。当前主要在 Chrome 验证；iOS 的 `audio.volume`、Media Session 有限制。
- 不要承诺“后台倒计时绝对准确”。后台会被浏览器节流，项目里把它列为已知限制。
- 不要说“axe 0 违规就代表所有对比度都过了”。报告里还有对比度需人工确认的说明。
