# 验收测试记录

测试环境：Windows 11，Chrome（无头模式）。
视口：320×568、375×812、414×896。
当前内置音频为 20 秒 WAV 占位素材（`white.wav` / `rain.wav` / `ocean.wav`）；播放时优先请求同名 MP3，失败后回退 WAV；早期功能验收在原始 MP3 素材上完成，播放路径与元素一致。本地 MP3 已加入 `.gitignore`，不随仓库提交。
测试方式：逐项操作并读取 DOM 与 audio 元素属性。到点测试把 `setInterval` 临时加速后跑完 15 分钟；淡出测试再把 `Date.now` 加速，验证最后 30 秒的音量曲线。自定义音频上传一首 9.6MB 的流行音乐验证正常路径；另用 11MB 文件、`.txt` 文件和伪造的 `.mp3` 验证拒绝与解析失败路径；另生成 100Hz + 10kHz 双音 WAV 检查左右频段覆盖，用短噪声检查压缩后的柱高。页面上的正式档位仍为 15 / 30 / 60 分钟。

## 异常场景

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| 连续点击播放 | 通过 | 快速点击 3 次后处于播放态，同一时刻只有一个音频在播放 |
| 播放中切换声音 | 通过 | 旧声音立即停止，新音源就绪，按钮复位为“播放” |
| 暂停后重新播放 | 通过 | 重新播放正常出声，暂停时定时已清零 |
| 音量调到 0 | 通过 | 内置声音 `audio.volume` 为 0；自定义音频 GainNode 为 0；无头环境无法验证实际听感 |
| 连续切换不同声音 | 通过 | 同一时刻只有一个音频在播放，多次切换没有叠加 |
| 倒计时结束后真正停止 | 通过 | 加速跑完 15 分钟后 `paused=true`，档位与倒计时都复位 |

## 定时启动行为

| 操作 | 结果 |
| --- | --- |
| 暂停时点击 15 分钟 | 显示 15:00，档位选中，1.2 秒后仍是 15:00，不倒计时 |
| 再点击播放 | 倒计时开始，1.2 秒后显示 14:59 |
| 播放中点击档位 | 从整段时长立即开始递减 |

| 项目 | 结果 | 依据 |

## V1.2 自定义音频检查

| 项目 | 结果 | 依据 |
| --- | --- | --- |
| 上传小于 10MB | 通过 | 上传 9.6MB 流行音乐后第四个卡片启用并选中，播放区显示文件名，音源为 blob URL，可播放 |
| 超过 10MB | 通过 | 11MB 文件被拒绝，提示“音频文件需要小于 10MB。”，原音频不变 |
| 非音频文件 | 通过 | `.txt` 被拒绝，提示选择音频文件 |

| 切换内置声音 | 通过 | 自定义播过后切内置声音，主 audio 正常播放，Web Audio 只接自定义那一路，未影响内置声音 |
| 定时与淡出 | 通过 | 自定义音频同样遵守预设档位、播放后计时、最后 30 秒淡出、到点停止与音量恢复 |
| 频率覆盖 | 通过 | 100Hz + 10kHz 双音 WAV 下左端和右端各有柱子，右端不再空白；频段为 35Hz–12kHz 对数分布 |

| 无法解析文件 | 通过 | 上传伪造的 `.mp3` 后立即弹出“音频无法解析”对话框，关闭后重新上传有效文件可恢复 |
| 刷新 | 通过 | 刷新后自定义不可用，回退白噪音，上传按钮恢复“上传” |
| 四列布局 | 通过 | 320 / 375 / 414 无横向滚动；375×812 一屏；四列卡片宽 60 / 67 / 76px |

## 布局与无障碍

- 320 / 375 / 414 三种宽度下 `scrollWidth` 等于视口宽度；375×812 全页 812px，一屏显示。
- 播放按钮高 56px，声音选项在 375 下 82px、320 下 76px，定时档位 46–48px，上传按钮 34px。
- axe-core 审计 0 项违规；渐变与毛玻璃背景让对比度检查被标为“需人工确认”，按配色值核算正文对比度在 5:1 以上。
